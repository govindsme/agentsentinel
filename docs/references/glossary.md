# Glossary

Definitions of key terms used across this site. The machine-readable glossary is in
`data/glossary.json`.

| Term | Definition |
|------|------------|
| **AI system** | A machine-based system that infers, from inputs, how to generate outputs (predictions, content, recommendations, decisions) that influence environments. |
| **Agentic AI** | AI systems that pursue goals with a degree of autonomy, often using tools, memory, and delegation to act in an environment. |
| **Prompt injection** | An attack that manipulates an LLM through crafted inputs, including indirect injection via content consumed from tools or documents. |
| **Data poisoning** | Adversarial manipulation of training data to degrade, bias, or backdoor model behavior. |
| **Model extraction** | An attack that reconstructs model behavior (or weights) through queries, enabling theft or further attacks. |
| **Membership inference** | Determining whether a specific record was part of a model's training data. |
| **High-risk AI system** | Under the EU AI Act, AI systems in specified high-impact use cases subject to mandatory requirements. |
| **GPAI** | General-Purpose AI model — a model with significant generality performing a wide range of tasks, subject to EU AI Act obligations. |
| **AI inventory** | A catalog of all AI systems and models used by an organization, the basis for risk assessment. |
| **Red teaming** | Adversarial testing simulating attacks to identify vulnerabilities before release. |
| **Model drift** | Degradation of model performance over time due to changes in input distribution or environment. |
| **RAG (Retrieval-Augmented Generation)** | Augmenting a model's knowledge by retrieving content from an external store at generation time. |
| **DPIA** | Data Protection Impact Assessment — a GDPR-required assessment of processing risks to individuals. |
| **AIMS** | AI Management System — the framework defined by ISO/IEC 42001 for governing AI. |
